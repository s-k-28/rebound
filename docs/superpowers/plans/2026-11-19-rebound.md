# Rebound Implementation and Release Plan

> **For agentic workers:** Execute the independent workstreams in parallel as requested by the user, using at most four active workers including the lead. Use superpowers:executing-plans for task execution; steps below track actual acceptance gates.

**Goal:** Deliver a useful Python transfer-recovery workspace, with verified address discovery and testnet recovery checks, then demonstrate the real supported flow before calling it hackathon-ready.

**Architecture:** Python/Flet renders the browser interface; FastAPI, HTTPX, pure protocol functions and SQLite provide discovery and reconciliation. A local-only Python CLI prepares again, confirms the actual signer and broadcasts at most once. A real QuickNode Stream can extend the candidate index but never bypasses canonical verification.

**Tech Stack:** Python 3.13+, Flet 1.1.2, FastAPI 0.165.0, HTTPX 0.28.1, eth-abi 6.0.0, eth-account 0.14.0, SQLite; pinned uv.lock. Manrope font under SIL OFL.

**Spec:** [PRD](../../PRD.md), [design references](../../DESIGN-SOURCES.md), [validation evidence](../../VALIDATION.md).

## Global Constraints

- Python application code; no authored application HTML, CSS or TypeScript. The optional QuickNode filter runs in the provider's required JavaScript environment.
- Only Base Sepolia (84532/domain 6) → Arc Testnet (5042002/domain 26), native source USDC and supported CCTP V2 burns.
- Original recipient is immutable; recovery must never create a new burn.
- No web signing key; local-only testnet execution requires explicit terminal confirmation.
- Source receipt, canonical block, original burn, matching message, caller rule, destination nonce and expiry are verified again before preparation.
- Simulation must succeed from the actual caller before exporting the unsigned mint transaction.
- Example data is visibly labeled and cannot prepare or sign a transaction.
- Show exact history coverage and partial/unavailable states. No fabricated balances, recovery totals or success rates.
- No paid service purchase, mainnet action or unapproved account/security change is part of this plan.
- UBC deadline: November 20, 2026, noon CST. Prioritize one working route and the submission evidence over additional chains or unrelated bounties.

## Review Focus

1. **Identical burns in a batch:** one available nonce must never mark two source burns complete; ambiguous matches stay unsupported.
2. **Retries and outages:** failed log ranges are not silently omitted; read-only retry/backoff cannot cause repeated broadcasts.
3. **Changed state after review:** a consumed nonce, changed caller, changed recipient or altered transaction after approval must stop local signing.
4. **UI mode and state changes:** changing search/filter/selection or returning from examples must not retain an unsafe ready action or disguise sample data as live.
5. **Money representation:** six-decimal amounts and large uint256 values retain every digit; original amount, fee and net amount remain distinct.

## Definition of done and bug policy

“Done” means the agreed milestone's checks pass with no known critical/high-impact defect, and limitations are visible. It never means a mathematical guarantee of zero bugs. An inaccurate recipient/amount, unauthorized caller, false completion, fixture signing path or repeated uncertain broadcast blocks release. A newly found failure is reproduced, fixed and regression-tested before continuing. Stop adding features once the agreed checks pass; spend the remaining time on the live evidence and submission.
